The primitive message sub-suite includes 12 boundary tests, one differential
integration test, and one documentation example. The differential test checks 64 independently
generated C packets containing 6,144 mixed operations. It decodes those packets
at all 21,458 storage split boundaries, including empty first/second slices.
Expected bytes are never generated by the Rust implementation under test.

Boundary coverage includes every bit width 0..32 at every initial alignment,
all invalid widths 33..255, exact capacity, truncation, atomic failures, cached
bits after byte exhaustion, backing-buffer reuse, 128 KiB limits, signed fields,
and special IEEE 754 binary32 representations.

The source-size policy was also exercised with a temporary 401-line Rust file;
it rejected the file, which was then removed. Largest handwritten source file:
233 lines. The largest generated source is a 287-line codebook. First-party Rust
forbids unsafe code; protocol has no third-party dependencies, and ordinary
transport depends only on protocol.

Historical Linux checks used a separate target directory. The user subsequently
required the normal repository target directory exclusively and stopping the
verified old development process before rebuilds. Native rechecks now follow
that policy; do not create alternate WSL/preview caches for future validation.
Both native platforms regenerated the same fixtures. CI is defined
for Windows and Linux but has not run on a hosted GitHub repository.

The expanded suite before pretty-log tests contained 71 native tests plus one
documentation example on Windows, with one extra SIGTERM test on Linux. Three
console-format tests were then added and passed debug/release checks for both
affected packages on both platforms. Real UDP process/file tests verify response
shape, lifecycle metrics, flush, filters, spans, shutdown, and exclusion of wire
secrets. Pretty/JSON defaults and forced/disabled colors are tested explicitly.

Additional independent evidence includes 116 wire fixtures (20 channel packets,
12 token cases, eight info cases, 64 index streams, and 12 message strings), 257
Huffman symbol entries, 32 original compression/decompression streams, and 49
XOR cases. One XOR case records the deliberate stale-empty-command safety
difference. All four original C artifact generators passed both platforms.

Boundary tests exercise index/string limits, fragment state, cancelled sends,
reserved codes, atomic failures, and expansion budgets. Deterministic stress
covers 4096 mixed hostile inputs and every 65536 two-byte compressed input;
it is not coverage-guided fuzzing.

These checks do not establish full peer interoperability, a playable server,
authentication, map/asset loading, expanded engine capacity, GSC behavior,
performance improvement, complete fuzz coverage, or production readiness.

The later asset catalog passed ten Windows debug/release tests and warnings-denied
Clippy. It retained 6,500 synthetic assets, including 5,000 images and 1,500 models,
and reused one slot through 10,000 unload/reload cycles without reusing handles.
Budget rejection preserves data/accounting; case/kind/raw-byte names, wide sizes,
stale/cross-catalog IDs, and exhausted generations are covered. These tests prove
encoded storage behavior, not decoded asset residency or legacy client expansion.

The later content boundary passed fifteen Windows debug/release tests and
warnings-denied Clippy/rustdoc, with three additional real verifier-process tests.
Eighteen independent synthetic Python ZIP fixtures exercise stored/DEFLATE data,
ZIP64 footers/local headers, precedence, corruption, and malformed paths/headers.
Thirty-two pinned-original-C vectors verify seven byte-path comparisons and 25
seeded legacy archive checksums. A 66,000-entry synthetic ZIP64 archive passes;
compressed expansion, forged output lengths, repeated payload references, payload
spans crossing the directory, all truncations of a sample, and deterministic byte
mutations are covered. Hidden corrupt duplicates fail full verification while the
visible override remains readable. Eight admission resources have exact/one-less
boundary coverage. All five C generators and independent archive regeneration
passed; prior workspace gates passed before the final integration, followed by
affected content/server gates. New content Linux validation remains open.

The executable's `--verify-iwd` mode verifies immutable bounded snapshots without
opening sockets or extracting files. It returns nonzero on invalid content,
reports aggregate counts/checksums, and process tests exclude names, payloads,
and local paths from logs. These tests do not establish decoded map/fastfile
loading, pure-server admission, stock-client ZIP64 support, or gameplay.
