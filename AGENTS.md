# Project contract

This repository is a standalone Rust rewrite of the CoD4X dedicated server.
Existing CoD4/CoD4X clients, maps, and mods are compatibility targets. ApX is a
future consumer, not a core dependency. Do not read or modify the Deathrun
workspace as part of this project. Do not use Graphify.

Remove inherited engine capacity ceilings through configurable storage and wide
internal identifiers. Legacy wire/client/asset-format bounds belong to named
compatibility profiles, never global engine allocation rules. Preserve the full
content catalog: the user's prior character/prestige/image cuts must not become
the new engine's design. Expanded client-visible capacity needs negotiated peer
support; never truncate IDs, silently remove content, or claim old clients can
represent unsupported features. Read docs/limits.md before designing storage.

Read README.md, docs/engineering.md, docs/architecture.md, docs/compatibility.md,
and docs/roadmap.md before changing the architecture or claiming compatibility.

Follow Google's Rust Style Guide, as adapted explicitly in docs/engineering.md.
GSC is a core expansion target, not merely a legacy VM port. Preserve existing
scripts through a compatibility mode; richer language features, built-in services,
asynchronous I/O, and developer tooling belong in the Rust engine and must not
require native CoD4X plugins. Keep extensions versioned and use wide runtime IDs/
configurable budgets. Read docs/gsc-runtime.md before designing this subsystem.
Do not claim GSC is implemented based on plans, content readers, or an empty crate.
Implement leaf modules, use explicit imports and typed errors, document public
APIs, and keep unsafe code forbidden. All crates must inherit workspace lints.
Do not add speculative crates, placeholder implementations, or unused abstractions.

Network and asset input is untrusted. Validate lengths before indexing or
allocation; enforce resource limits; do not panic on malformed input. Keep valid
wire behavior distinct from intentional changes to invalid-input behavior.

The pinned upstream revision and source hashes live in upstream.lock.json.
Preserve upstream provenance and license notices. Reference C/assembly is test
and research material; it must not become a runtime dependency of the Rust server.

Run cargo fmt --all -- --check, cargo clippy --workspace --all-targets -- -D warnings,
cargo test --workspace --locked, cargo test --workspace --release --locked, and
cargo doc --workspace --no-deps --locked with RUSTDOCFLAGS=-Dwarnings.
Regenerate differential fixtures with tools/generate_message_vectors.py when
changing codec behavior or the source baseline; generated bytes must match.
Run tools/generate_wire_vectors.py with --check for channel, command, and info
behavior. Emit structured low-cardinality operational events. Never log packet
contents, challenges, authentication tokens, passwords, or entire configurations.
Aggregate rejected traffic instead of producing an event for every bad datagram.
Verify generated compression data with tools/generate_huffman_vectors.py --check.
Verify keyed payload fixtures with tools/generate_obfuscation_vectors.py --check.
Verify archive fixtures with tools/generate_archive_fixtures.py --check and
original filesystem vectors with tools/generate_content_vectors.py --check.
Verify player-command fixtures with tools/generate_user_command_vectors.py --check.
Verify independent cookie fixtures with tools/generate_cookie_vectors.py --check.
Verify BSP fixtures with tools/generate_bsp_vectors.py --check.
Verify independent fastfile envelopes with tools/generate_fastfile_fixtures.py --check.
Verify independent zone root tables with tools/generate_zone_fixtures.py --check.
Verify serialized block offsets with tools/generate_zone_pointer_vectors.py --check.
Verify typed raw files with tools/generate_rawfile_fixtures.py --check.
Development logs default to readable output; process tests requiring JSON must
pass --json-logs explicitly. The user requires one normal target directory:
never use --target-dir, set CARGO_TARGET_DIR, or create separate preview/WSL build
caches. Before rebuilding, stop the old local development server after verifying
its executable belongs to this repository. Do not stop unrelated processes or
production servers. This explicit user authorization supersedes the earlier
local-development no-stop rule; remote deployment/administration stays separate.
On Windows run tools/stop-dev-server.ps1 before rebuilding the process. It checks
the exact repository-owned debug/release executable paths before stopping them.
Report what was verified, what remains unimplemented, and which acceptance gates
are still open. Passing round trips alone is not compatibility evidence.

Do not deploy, publish, or change a production server as part of local development.
Any later remote administration or transfer must use Teleport tsh, never OpenSSH.
Do not print credentials or commit private configuration or proprietary assets.
